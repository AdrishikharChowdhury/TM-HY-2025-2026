# Working instructions

- Treat this folder as the source project for *Electronic Trends*, the ECE department magazine at St. Thomas' College of Engineering & Technology.
- Preserve the confirmed issue identity: Volume X, 2025â€“26. Correct any stale Volume IX references when editing magazine material.
- Follow the folder map and LaTeX build guidance in the root `README.md`. Keep article sources, front matter, events, activities, assets, submissions, and build output in their current categories; update LaTeX paths whenever files move.
- Keep `.gitignore` aligned with generated LaTeX output and local editor/OS clutter. Do not ignore submitted source material or reviewed publication PDFs by default.
- Publication PDFs exceed GitHub's regular 100 MB file limit; commit the `*.pdf` Git LFS attributes before commits that add PDFs, and migrate already committed PDF history when needed before pushing.
- In magazine reports, place tables at page tops or bottoms; do not pin them mid-page. Keep any explanatory lead-in adjacent to the table without pushing the table away from the page edge; when the lead-in would displace a top-placed table, put the lead-in immediately after it. Ensure following sections do not overtake the table in rendered reading order. Avoid forced breaks or spacing that leave large blank areas.
- Keep explanatory sentences introducing tables within one column; the tables may span the full page width when the layout requires it.
- If a bottom-placed full-width table will not fit because its above-table lead-in lengthens the flow (leaving the table on the next page or the columns uneven), move the unchanged lead-in into the bottom float directly above its caption at full width. This keeps the text columns level, keeps the lead and table on the same page, and still puts the table at the page bottom.
- Keep each table's citation or explanatory lead-in on the same page as its table. When a table is placed at the top and an above-table lead-in would push it down, place the unchanged lead-in immediately after the table within the same float, at one-column width.
- When several tables would stack at the top of one page, distribute them across adjacent page edges where the layout allows, keeping each citation with its table and avoiding large blank areas.
- In Report 1, align Table 1's lead-in to the right column immediately above the bottom-placed full-width table.
- Leave a small visible gap between a full-width table and any lead-in sentence placed immediately below it.
- Use a consistent light yellow background for all “Did you know?” boxes. When the user asks to split a fact into points, preserve its existing facts and wording without adding new claims.
- When the user explicitly asks for new technical facts, add only the requested number and verify them against authoritative sources.
- Keep visible separation between points in boxed “Did you know?” lists when requested.
- Keep consecutive report sections in one continuous `multicols` flow; closing and reopening columns mid-article can cause later left-column headings to appear before earlier right-column text.
- The user is the editor, not the report author. Do not add, remove, paraphrase, or invent report content unless explicitly asked; make layout-only changes and preserve the author's wording.
- When the user asks to check a report for “discrepancies,” interpret that as checking wording consistency and content/reading sequence (including misplaced lead-ins, citations that do not match the reference list, and unbalanced columns that leave one column visibly shorter than the other); do not treat it as a request for technical fact-checking unless asked.
- For a sequentialization review, inspect the rendered report from beginning to end in actual two-column reading order across page breaks, then compare that order to the source. Do not stop after checking float lead-ins or source order.
- After every report layout change, render and inspect the affected PDF pages for blank areas below figures, table placement, and reading order before telling the user the change is complete. A successful LaTeX build alone does not confirm the layout rules are met; do this automatically without waiting for the user to point out a gap.
- After every change, inspect the rendered pages for content sequence, column order, spacing, and float placement before considering the change complete. Never assume the layout is correct from the source or a successful build; check it in the PDF.
- For every new instruction the user gives in this project, update both `AGENT.md` and `CONTEXT.md`: add durable working guidance here when appropriate, and record the request, relevant decision, and outcome in `CONTEXT.md`.
- Before starting work in a later session, read this file and `CONTEXT.md` for the accumulated instructions and project context.
- Keep `CONTEXT.md` as a concise, current handoff; update or consolidate it as work progresses.
- Avoid optional MiKTeX font-package probes in the main preamble when the document does not require that font; they can trigger recurring package-install prompts. Keep builds noninteractive where possible.
- When a column ends early because an inline figure block does not fit (the pin), prefer shrinking that figure just enough to fit instead of moving text; then re-check the whole document, because a successful fit pulls all later content up and can move gaps, table placements, and report starts onto other pages.
- Never leave a report title/author stranded at a page bottom with its abstract beginning on the next page. After any reflow, check each report start (author-line y vs page-last text); fix a stranded title with layout-only spacing trims immediately above it so the abstract starts on the same page, not by forcing the title block to the next page.
- When extending a "Did you know?" box to push a following report onto the next page, size the extended box so it fills to near the page bottom (leave less than ~45 pt) — a partial fill can strand the report title. When a reflow splits an inline table from its lead-in, guard the lead with `\needspace{<lead+table height>}` so the lead moves to join the table, not the reverse.
- Paired photos in the vision/mission and about pages must render at the same height: use an explicit `height=` with no `width=\linewidth`, in equal-width minipages, so differing column widths cannot make one image width-bound and shorter.
- Do not embed a table inside a report's Conclusion section. Keep the table with its explanatory lead-in before the Conclusion heading (editor preference).
- When converting a full-width table to a single-column inline table, merge the adjacent `multicols` flows so the table and its lead stay in sequence. If a following block must be kept together across a flow boundary, place `\needspace` before `\begin{multicols}` at top level; a `\needspace` at the start of a `multicols` environment does not see the page position.
- When a report has two stacked `multicols` flows around a full-width table float, a later flow can backfill below the first flow's short left column while the first flow's right column is still running, producing a crossover. Merge the flows into one continuous `multicols` and convert the intervening full-width table to an inline column minipage immediately after its lead. Do not leave a full-width float inside the merged flow: LaTeX can silently drop it.
- When a box reduction reflows following reports, re-check the next report's start and every table pair. If a shortened box leaves a report title at a page bottom, free space only above it (preceding report references/padding/title spacing) so the abstract head joins the title on the same page; do not force the title to the next page. If an inline table's block follows intervening method paragraphs and its lead splits across pages, move the table directly after its lead (wording unchanged) so lead and table share a page and column.
- If a shortened box pulls a report up and a table's complete lead sits at a column bottom while the table starts the next page, do not leave the split or a large gap. Keep the lead with the table and, if the block still cannot fit in the remaining column, relocate the lead+table block within the same section to a position where it fits (for example, after the section's descriptions and before the next section). Wording, caption, and table content stay unchanged; verify the table remains in the same section, no later section overtakes it, and the lead/caption share the page.
- When the editor orders a table moved before a section heading, place the existing table immediately before that heading, keep the table whole, ensure the heading is not stranded, and disclose any resulting section-end blank. Do not restore a table lead sentence the editor removed.
- When replacing every "Did you know?" box across the reports, keep the boxes centralized at their report-order insertion points in `reports.tex` and remove the per-report `\input` hooks, so exactly one box per report is guaranteed. Verify the final wording from the built PDF, not just the source, and re-check every report start and table lead/caption pair after the reflow.
- A `\needspace` inside a `multicols` can force an unwanted column break even when the guarded block would fit; if a table fits, remove the guard (or place it at top level) rather than shrinking the table. When a large inline table leaves a mid-report column gap, relocate the whole table within its section — wording, caption, and content unchanged — instead of forcing breaks.
- To keep an abstract on the same page as its report title when the preceding page is tight, trim spacing only above the title and reduce `\premulticols` locally in a group around that report's `multicols` environment (restoring the default afterward), so the title, author, and abstract start together without disturbing other reports.
- When the editor asks that every report/topic start on a separate page, put `\clearpage` before each report `\input` (not before the first) in `reports.tex`. Rebuild and verify that each number/title is the first content line on its page and that the abstract stays on that page. Then check the "Did you know?" boxes: if one lands alone on a page, reclaim space in that report (reference font/itemsep or local paragraph spacing) or compact the shared box padding; do not leave a box-only page. Inline tables inside `multicols` must size columns with `\columnwidth`, not `\textwidth`, or they overflow the column.
- If a new report starts a fresh page and a table lead is left at the bottom of the preceding page, add `\needspace{<lead+table height>}` before the lead so the lead moves down with the table; re-check that the guard does not create a large mid-report gap.
- To balance the two columns of a `multicols` report, render the page at high DPI and also measure the last text baseline in each column from `pdftotext -bbox` (ignore the running header). Prefer reclaiming or adding real space (adjust a figure's width, or place a full-width table between the two-column blocks) over negative `\vspace`, which collapses the heading's breathing room and looks cramped. A short column often means an unbreakable figure or box did not fit; enlarging or moving that element is usually the cleanest fix. Always re-render the page and the following page to confirm no heading is stranded and no new gap appears.
- A full-width table must sit at a page top or bottom. If a table would otherwise land mid-page between two text blocks, extend the preceding `multicols` through later sections until the text fills the page above the table, close the flow, place the table as a `[!b]` float at the page bottom, and restart `multicols` on the next page. Move the unchanged lead sentence to the end of the right column directly above the bottom table (the R1 pattern). Verify from `pdftotext -bbox` that the caption is in the lower page area and the last row reaches near the text-block bottom, not the page middle.
- When a merged `multicols` report contains an unbreakable inline table block that jumps to the top of one column (leaving the other column ~100+ pt short), convert the table into a full-width `table` float declared before the merged flow and pin it to a page edge with `[!b]` or `[!t]`; the float queue distributes successive tables across adjacent page edges without closing the flow. Never place a full-width `table` float inside `multicols` — the package warns and drops it. Re-measure text-only baselines (`pdftotext -bbox`, excluding the table band) and inspect the rendered pages.
- A single-column inline table sitting at the top of the second column can also leave that column short (the R14 p. 72 case, ~45 pt). If the table has no lead sentence, convert it to a full-width `[!b]` float at the page bottom and let the text reflow above it; verify the text-only baselines end level above the table and that the following pages are unchanged.
